Q1.1 Insert a row in the DEPARTMENT table that references a row in the EMPLOYEE table. Then try to delete the referenced row. What will happen?
- SQL used:
  INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date) VALUES (4, 'Marketing', 101, '2023-01-01');
  DELETE FROM EMPLOYEE WHERE ssn = 101;
- Output / Error:
  ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (company.department, CONSTRAINT department_ibfk_1 FOREIGN KEY (mgr_ssn) REFERENCES employee (ssn))
  - Explanation: MySQL rejects the deletion because it violates referential integrity (the employee is referenced as a manager in the department table).

Q1.2 Insert a row in the PROJECT table that references a row in the DEPARTMENT table that doesn't exist yet. What will happen?
- SQL used:
  INSERT INTO PROJECT (Pnumber, Pname, Plocation, Dno) VALUES (40, 'Delta', 'Aswan', 99);
- Output / Error:
  ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (company.project, CONSTRAINT project_ibfk_1 FOREIGN KEY (Dno) REFERENCES department (Dnumber))
  - Explanation: MySQL rejects the insertion because department number 99 does not exist in the referenced DEPARTMENT table.

Q1.3 If mgr_ssn and Dno are both NOT NULL, how will you insert the first row in EMPLOYEE or DEPARTMENT?
- Explanation: 
  If both foreign keys have strict NOT NULL constraints creating a circular dependency, it becomes impossible to insert the very first row independently because each requires a valid record in the other table to exist first. 
  To solve this in SQL, one can either:
  1. Temporarily allow NULL on one of the foreign key columns during table creation, insert the initial records, update them, and then alter the column back to NOT NULL.
  2. Use a transaction or disable foreign key checks temporarily using SET FOREIGN_KEY_CHECKS = 0;, insert the rows, and then re-enable them using SET FOREIGN_KEY_CHECKS = 1;.
